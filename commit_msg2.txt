Surface silent startup crashes + add system-tray entry point

Fixes the user-reported "WinMeters does not start, not showing in Task
Manager" symptom by making startup failures visible and giving the user
a persistent, taskbar-adjacent surface to find the running process.

App.xaml.cs -- wire crash sinks before StartupUri fires:

  * AppDomain.CurrentDomain.UnhandledException: log via WinMeters.Log.D
    + MessageBox so any unhandled exception on any thread surfaces
    visibly instead of dying silently and leaving the user wondering.
  * DispatcherUnhandledException: log + MessageBox, mark Handled=true,
    call Shutdown() so the app exits cleanly and OnExit releases the
    single-instance mutex.

OnStartup reordered: single-instance mutex acquired FIRST, before
base.OnStartup. Wrapped in try/catch on AbandonedMutexException --
previous instance crashed via kill -9 inside a fullscreen game is the
common cause; BCL throws on the next acquire but quietly grants the
caller ownership, so we recover by setting createdNew=true and letting
OnExit skip ReleaseMutex for the unassigned wrapper.

MainWindow.xaml.cs -- persistent NotifyIcon tray entry:

  * System.Drawing.SystemIcons.Application tray icon, Text="WinMeters",
    Visible=true, lives for the entire process lifetime.
  * ContextMenuStrip with 4 items: Show Settings / Show-Hide Bar /
    Separator / Quit. MouseDoubleClick left-button -> Settings.
  * Created in ctor right before the Loaded/Closed/Deactivated
    subscriptions; disposed FIRST in MainWindow_Closed so the icon is
    gone the instant the bar closes.
  * All click handlers marshal through Dispatcher.Invoke -- NotifyIcon
    callbacks fire on a WinForms MessageOnlyWindow thread, not on the
    WPF UI thread.
  * Reuses MenuItem_Settings_Click and MenuItem_Exit_Click via
    synthetic RoutedEventArgs so cleanup logic stays in one place.

app.manifest -- DELIBERATELY NOT RELAXED to asInvoker.

Win32 RegisterHotKey requires the hooking process to be at-or-above
the foreground process's integrity level to capture keyboard input in
fullscreen-game windows. Relaxing the manifest would silence UAC
prompts but break the global hotkey in fullscreen games, which is
WinMeters' core value proposition. The WnForms.NotifyIcon tray entry
point is the right answer to the visibility complaint without
sacrificing the hotkey.

Validation: 0 build errors (only 2 pre-existing CS8600 nullable
warnings in SettingsWindow.xaml.cs), 39/39 unit tests pass.
